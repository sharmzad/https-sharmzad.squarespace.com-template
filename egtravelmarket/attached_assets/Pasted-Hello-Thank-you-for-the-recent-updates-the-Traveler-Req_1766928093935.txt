1️⃣ Accepted Offer State – Missing Traveler Actions
Current situation:

Offers show statuses like:

“Awaiting your decision”

“Accepted”

Accepted offer is highlighted correctly (green border)

❌ Problem:

There is no clear action path for the traveler once an offer is accepted.

✅ Required:

When an offer is accepted, the UI must clearly show next steps, such as:

A clear message:

“You have accepted this offer. Proceed to payment to confirm your booking.”

A single primary CTA button (even if payment logic is added later):

Proceed to Payment (disabled or placeholder is fine for now)

This is critical for user clarity and conversion psychology.

2️⃣ Accept / Reject Buttons Visibility (Consistency)
Current issue:

In some offer cards, the traveler sees status text only

In others, actions are unclear or missing

Required behavior:

For each offer card before selection:

Show:

Accept Offer (primary)

Reject Offer (secondary)

After acceptance:

Accepted offer:

Highlighted

Status = Accepted

Action buttons removed

Other offers:

Disabled

Status = Not Selected

3️⃣ Provider Profile Access (PARTIALLY FIXED – NEED CONSISTENCY)
Current:

Some offers show “View Profile”

Others do not

Required:

Every offer card must include:

Provider name

Provider type badge (Guide / Agency / Dive Center / Mentor / Admin)

View Profile button (mandatory)

Verification badge (if verified)

This is essential for traveler trust.

4️⃣ Offer Card Information Hierarchy (UX CLEANUP)

Each offer card should clearly display:

Provider Name + Type

Provider Message

Total Price (USD)

Status badge:

Awaiting your decision

Accepted

Not selected / Rejected

Right now some cards feel visually empty or repetitive.

Suggested fixed text (can be reused everywhere):

“All payments and communications are secured by EgTravelMarket.
